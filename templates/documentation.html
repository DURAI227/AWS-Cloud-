1. System Architecture Overview

This deployment implements a resilient, enterprise-standard DevOps architecture utilizing:

  • Application Layer: Python 3.10+ Flask application with WSGI worker pooling provided by Gunicorn.
  • Web Server & Reverse Proxy: Nginx listening on Port 80/443, proxying to Gunicorn UNIX socket or 127.0.0.1:5000 with Gzip compression and security headers.
  • Process Supervisor: Linux systemd daemon (flaskapp.service) ensuring automated restart on failure and auto-start on EC2 boot.
  • Cloud Infrastructure: AWS EC2 (Ubuntu 24.04 LTS), AWS S3 for automated pre-deployment tarball snapshots, IAM Instance Profiles for secret-less credential rotation.
  • CI/CD Engine: Jenkins Declarative Pipeline with 6 automated stages (Checkout → Build → Test → Backup → Deploy → Verify).
2. Local Installation & Verification

To run the application locally on any workstation:

# 1. Clone repository
git clone {{ github_repo }}
cd aws-cloud-deployment

# 2. Create virtual environment
python -m venv venv

# 3. Activate virtual environment
# On Linux / macOS:
source venv/bin/activate
# On Windows PowerShell:
.\venv\Scripts\Activate.ps1

# 4. Install dependencies
pip install -r requirements.txt

# 5. Run automated test suite
pytest -v tests/test_app.py

# 6. Start development server
python app.py
# Server runs on http://127.0.0.1:5000
3. AWS EC2 Setup (Ubuntu 24.04 LTS)

Follow these steps to prepare your EC2 instance:

  1. Launch an EC2 instance:
    • AMI: Ubuntu Server 24.04 LTS (64-bit x86)
    • Instance Type: t3.micro (Free Tier eligible) or t3.small
    • Key Pair: Create or select an SSH key pair (e.g. ec2-key.pem)
    • Security Group: Inbound rules:
      • SSH (Port 22): restricted to your IP / Jenkins IP
      • HTTP (Port 80): 0.0.0.0/0
      • HTTPS (Port 443): 0.0.0.0/0
  2. Connect to the server and execute the automated setup script: 
    # SSH into EC2 instance
ssh -i /path/to/ec2-key.pem ubuntu@<YOUR_EC2_PUBLIC_IP>

# Clone repo and execute setup script
git clone {{ github_repo }} /var/www/flaskapp
cd /var/www/flaskapp
chmod +x scripts/*.sh

# Run automated EC2 configuration script
sudo ./scripts/setup_ec2.sh
4. AWS S3 Bucket & IAM Least-Privilege Policy

Create a secure, private S3 bucket and attach an IAM Instance Profile to EC2:

# 1. Create S3 Bucket via AWS CLI
aws s3 mb s3://my-flaskapp-deploy-backups-bucket --region us-east-1

# 2. Block all public access
aws s3api put-public-access-block \
    --bucket my-flaskapp-deploy-backups-bucket \
    --public-access-block-configuration "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"

# 3. Enable AES-256 Server-Side Encryption
aws s3api put-bucket-encryption \
    --bucket my-flaskapp-deploy-backups-bucket \
    --server-side-encryption-configuration '{"Rules": [{"ApplyServerSideEncryptionByDefault": {"SSEAlgorithm": "AES256"}}]}'
Least-Privilege IAM Policy for EC2 Instance Profile:
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowS3BackupOperations",
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:ListBucket"
      ],
      "Resource": [
        "arn:aws:s3:::my-flaskapp-deploy-backups-bucket",
        "arn:aws:s3:::my-flaskapp-deploy-backups-bucket/*"
      ]
    }
  ]
}
5. Jenkins CI/CD Pipeline Implementation

The included Jenkinsfile defines a complete declarative pipeline. To configure Jenkins:

  1. Install required Jenkins plugins:
    • Pipeline
    • Git plugin
    • SSH Agent plugin
    • AWS Steps / Credentials plugin
  2. Add Jenkins Credentials (under Manage Jenkins → Credentials):
    • ec2-ssh-key: SSH Private Key with passphrase (for user ubuntu).
    • aws-credentials: AWS Access Key ID & Secret Access Key (if IAM role is not on Jenkins node).
  3. Create a new Pipeline job pointing to your GitHub repository and set script path to Jenkinsfile.

7. DevOps Troubleshooting Runbook

Check logs with: sudo journalctl -u flaskapp.service -n 50 --no-pager. Verify virtual environment path in /etc/systemd/system/flaskapp.service and check file permissions for /var/www/flaskapp.

Verify Gunicorn is actively listening on port 5000: curl -I http://127.0.0.1:5000/health. Ensure Nginx upstream matches http://127.0.0.1:5000. Inspect Nginx error log: sudo tail -n 50 /var/log/nginx/error.log.

Ensure the S3 bucket exists, S3_BUCKET_NAME environment variable is set, and the IAM role or AWS credentials attached to the Jenkins node have s3:PutObject permission on the bucket.
